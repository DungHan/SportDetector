## Context

Builds on three already-proven pieces: the detector interface + null-object + onnx-impl pattern (`IPlayerDetector`/`NullPlayerDetector`/`OnnxPlayerDetector`, `ICourtKeypointDetector`/... in `src/NBA.Vision`); `OnnxModelPipeline`'s generic preprocess→run→postprocess wrapper (`src/NBA.Inference`); and `IPlayerTracker`'s per-frame `Update(...)` shape, which reports only currently-live tracks and has no explicit "track terminated" event — `MainWindowViewModel`/the minimap already infer termination purely by a track ID's absence from one frame's `Update(...)` result to the next. This capability lives in a new `src/NBA.JerseyOcr` project (registered in `NBA.slnx`) rather than the pre-existing `src/NBA.OCR` scaffold this change originally targeted — a concurrently-merged scoreboard-OCR change claimed `NBA.OCR` for unrelated broadcast-text recognition before this change landed, so `NBA.JerseyOcr` avoids the collision; `tests/NBA.JerseyOcr.Tests` is the matching new test project. `MainWindowViewModel.ProcessFrameArrived` already computes `trackedPlayers` every frame, independent of sport classification/calibration state, and uses `$"#{t.TrackId}"` as both the raw-overlay box label and the minimap marker label. See proposal.md for motivation and scope.

## Goals / Non-Goals

**Goals:**
- Define `IJerseyNumberRecognizer` (crop in, number+confidence or "unrecognized" out) with `NullJerseyNumberRecognizer` and `OnnxJerseyNumberRecognizer`, following the existing detector pattern.
- Define a per-track vote aggregator that turns a stream of per-frame recognition results into a stable resolved number per track, with no explicit termination hook — driven purely by which track IDs are present in each frame's input, mirroring how the tracker/minimap already treat track lifetime.
- Wire crop extraction + recognition + voting into `MainWindowViewModel.ProcessFrameArrived`, and change only the **minimap** marker label to the resolved number (falling back to track ID); the raw-overlay box label is explicitly unchanged (see Non-Goals).
- Make the vote aggregator independently unit-testable with hand-constructed per-frame result sequences, no model or fixture asset needed (mirrors `NBA.Tracking.Tests`'s style for `ByteTrackPlayerTracker`).

**Non-Goals:**
- Changing the raw overlay's box label away from track ID. The proposal only promises the minimap marker label changes; the raw view keeps showing `#{TrackId}` on the labeled box, unchanged. A future change can revisit that independently if wanted.
- General variable-length OCR (sequence decoding, arbitrary text). See Decisions — jersey numbers are treated as a small closed classification set instead.
- Training or sourcing a real recognition model — same placeholder situation `vision/player-detection` and `vision/court-calibration` are already in; `NullJerseyNumberRecognizer` is the real runtime path until one exists.
- Jersey color extraction, team assignment, or any cross-track re-identification (see proposal.md).

## Decisions

**Jersey number recognition is closed-set classification (one class per number 0-99, plus a "no number" class), not general sequence-decoding OCR**, despite the project/namespace being named `NBA.JerseyOcr`. A basketball jersey number is always 0-99 (a bounded, small label set), so this reuses the same fixed-class-classification shape already proven twice in this codebase (`OnnxPlayerDetector`'s per-class confidence channel, `ClipZeroShotSportClassifier`'s prompt-embedding classification) instead of introducing CTC/attention-based sequence decoding machinery this codebase has no precedent for and no model to justify yet. `IJerseyNumberRecognizer.Recognize(...)` returns a `JerseyNumberRecognitionResult` shaped as `(int? Number, float Confidence)` (`Number: null` = unrecognized/no-number class won), not a decoded string. If a real model later needs true multi-digit sequence decoding (e.g. numbers above 99, or letters), that's a breaking change to this interface, not an extension of it - acceptable since no real model exists yet to lock in the simpler shape prematurely.

**Crop extraction is a new `ImagePreprocessing.ToNchwTensor` overload taking a source-space crop rectangle**, not a separate cropping utility. The existing overload already does source→target coordinate mapping for the *full* frame; the new overload takes `(cropX, cropY, cropWidth, cropHeight)` and maps target pixels into that sub-rectangle instead of the full source, reusing the same nearest-neighbor sampling loop. The crop rectangle is clamped to `[0, sourceWidth) x [0, sourceHeight)` before mapping, since a track's motion-predicted box (used during brief occlusion, `tracking/player-tracking`) can extend outside the frame. If clamping collapses the box to zero width or height, `OnnxJerseyNumberRecognizer` skips the model call entirely and returns "unrecognized" - a degenerate crop is not a model input, not a special model output to encode.

**Vote aggregation is plurality-with-threshold, recomputed fresh from accumulated counts each call, not a one-shot "lock in and never revisit" resolution.** `IJerseyNumberVoteAggregator.Update(IReadOnlyList<(int TrackId, JerseyNumberRecognitionResult Result)>)` (mirroring `IPlayerTracker.Update`'s per-frame shape) increments a per-track, per-candidate-number vote count for every non-null result, then returns the current argmax candidate per track wherever that candidate's count has reached `minVotes` (constructor parameter, default e.g. 5 - exposed rather than hardcoded, same posture as every other threshold in this codebase). Any track ID not present in the current call's input is dropped from internal state entirely (its counts discarded) - this is how track termination is detected, with no separate termination event needed, consistent with the tracker/minimap precedent in Context. Because resolution is "current argmax above threshold" recomputed every call rather than a one-time decision, a later candidate naturally displaces the resolved one only once it actually out-votes it (spec's "overtake" scenario), with no extra state or special-casing required.

**Recognition + voting run unconditionally alongside tracking, before the sport/calibration gates**, in the same place `trackedPlayers`/`playerAnnotations` are already computed - not gated behind a valid calibration. This lets vote counts warm up from the moment a track exists, so a resolved number is already available the moment calibration completes and the minimap starts plotting markers, rather than starting voting from zero at that point. Matches `vision/player-detection`'s existing "independent of sport/calibration state" posture, extended to this new step.

**No new UI toggle for recognition.** Recognition/voting always runs once a valid detector is wired (real or `Null`), same as player detection and tracking today - no user-facing on/off switch, consistent with how the existing per-frame pipeline steps compose.

## Risks / Trade-offs

- [No trained jersey-number recognition model exists yet] → `NullJerseyNumberRecognizer` (always "unrecognized") is the real runtime path until one exists; minimap markers keep showing track ID indefinitely until a model is wired in, which is a strict improvement over the pre-change state (nothing regresses).
- [Closed-set 0-99 classification instead of general OCR] → cannot represent letters or numbers above 99; acceptable for basketball (no such jerseys), would need a breaking interface change to extend to other sports/formats later.
- [Running a third ONNX model per tracked player, per frame] → same "performance tuning is a later concern" posture `add-player-detection`'s and `add-bytetrack-tracking`'s designs already took; N tracked players means N recognizer calls per frame, worth measuring once a real model exists, not blocking this change.
- [Plurality vote with no minimum-frame-count decay] → a track that briefly shows one wrong number many times before ever showing the right number could take longer to correct than to initially resolve, since old votes never expire. Accepted for a first version; a future change could add vote decay/windowing if this proves to matter in practice.
